# Writing and review

Use this order of authority:

1. The user's current request and facts.
2. The explicit ContentOps writing profile.
3. Patterns supported by approved examples.
4. General writing judgment.

Preserve the author's actual point of view. Never invent personal experience, outcomes, client details, statistics, or quotations. If a factual gap changes the meaning, ask or mark it as unresolved.

For a short walking note, produce one complete first draft when the central point is clear. Preserve the rough note as the source; do not replace it with polished copy. Avoid a questionnaire: ask one focused question only when a missing detail would change the meaning. A personal observation does not require an artificial research phase. Verify external factual additions or leave them out; make unresolved claims visible for review.

For revisions, use the current draft and the latest feedback. If the feedback already exists on the item, do not record it again just because a web handoff repeats the request. One-off feedback is not automatically a permanent voice preference.

For a strong professional post:

- Open with a specific tension, observation, or claim.
- Develop one central idea with concrete evidence or an example.
- Prefer clear language and short paragraphs over generic motivational phrasing.
- End with a useful conclusion or a genuine question; do not force engagement bait.
- Review for factual support, voice fit, redundancy, and unsupported certainty.

Treat feedback as version-specific. Save a material rewrite as a new immutable version and summarize the change.
